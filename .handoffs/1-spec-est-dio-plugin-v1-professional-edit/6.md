## What was built
- **The `/estudio:novo-projeto` skill** (`plugin/estudio/skills/novo-projeto/SKILL.md`) is the Entrevistador on the main thread.
  - It runs the full Projeto Grilling in pt-BR over the 16 catalogue topics. Questions are grouped 3–4 per turn, each with a recommendation and "decide você", and a one-paragraph answer is harvested for every topic it settles.
  - It accepts reference images and videos: it copies them into `kit/referencias/` and never touches her originals.
  - It stores logos, fonts and the end card in `kit/`.
  - It writes the pt-BR briefing and the Kit, then stops at the Kit approval Gate.
- **Two new CLI subcommands** in `plugin/estudio/scripts/estudio.mjs`:
  - `novo-projeto "<folder>" "<projeto>"` creates `projetos/<projeto>/` with:
    - `projeto.md`, one pt-BR section per catalogue topic, each holding the placeholder `_A preencher na entrevista._`;
    - `kit.json`, a complete, valid Kit with the defaults: Formato `9:16` and `musica.politica: "no-app"`;
    - `kit/`, the assets folder.

    On an interrupted Projeto it adds only the missing files. It never overwrites.
  - `aprovar-kit "<folder>" "<projeto>"` closes the Gate by stamping `aprovadoEm`. It refuses a Projeto with any `estado` error or any unanswered briefing section.
- **`estado` now checks the Projeto**:
  - It validates the Kit schema field by field.
  - It reports `briefing` (`completo` / `incompleto`) and `kit` (`pendente` / `invalido` / `aguardando-aprovacao` / `ok`).
  - `nextStep` gains `aprovar-kit`, and `concluir-projeto` now also fires while the briefing has unanswered sections.
- The Diretor skill (`estudio/SKILL.md`) now sends `novo-projeto`, `concluir-projeto` and `aprovar-kit` to the new skill.

## Decisions & deviations
- **Kit keys are pt-BR**, like every other Estúdio document. Unknown extra keys are allowed so later tickets can add fields (e.g. learnings in #17), but typos in optional extra keys go undetected.
- **The Kit is stored at `projetos/<p>/kit.json`, with assets in `projetos/<p>/kit/`.** The wiki's older "settled" note (`marca/tokens.json`) is superseded, and the wiki records that.
- **Asset paths** must be relative to the Projeto, start with `kit/`, and point to a file that exists.
- **The Grilling counts as complete when no briefing section holds the placeholder.** This is the deterministic marker that tells an interrupted Grilling apart from a finished one (spec review finding). `unansweredSections` is in `lib/briefing.mjs`.
- **The Kit Gate is always the Criadora's decision.** It is not versioned, has no Rodada counter, and Autonomia never auto-approves it (US21). Autonomia is #17, and Rodadas belong to Vídeos. This is a deviation from the full Gate primitive, recorded here on purpose.
- **Scope beyond the ticket's text.** These are small and justified:
  - Formato `1:1` is accepted, because the repo's menu already offers square.
  - Two extra music policies: `arquivo-dela` and `sem-musica`.
  - Name validation: portable folder names and NFC matching, so a Mac NFD name does not create a duplicate.
- **`aprovar-kit` reuses `estado`**, so validation cannot drift between the two. `lib/projeto.mjs` imports `lib/estado.mjs`.
- **`novo-projeto` also completes an interrupted Projeto.** Without that, `concluir-projeto` had no deterministic path.
- **`npm ci --ignore-scripts` was run in the worktree** because no `node_modules` existed anywhere. `node_modules` is gitignored.
