## What was built
- **`/estudio:projetos`** (`plugin/estudio/skills/projetos/SKILL.md`): the Diretor lists every Projeto and its Vídeos, with Status, Rodada and what waits for the Criadora. The list is built only from `estado` output.
- **`/estudio:editar-projeto`** (`plugin/estudio/skills/editar-projeto/SKILL.md`): the Entrevistador changes a Projeto's briefing (edited in place) or its Kit. The Kit is changed only through the new CLI command. The skill shows her "antes → depois" and applies the change only after she answers "aplicar". It then offers the unfinished Vídeos an opt-in to the new Kit.
- **New CLI commands** in `plugin/estudio/scripts/estudio.mjs`, with the logic in `lib/editar.mjs`:
  - `editar-kit "<folder>" "<projeto>" '<json>'` takes only the fields that change. Objects merge; any other value replaces the old one. It re-validates the merged Kit with `validateKit`, refuses a broken Kit without writing anything, freezes existing Vídeos and stamps `aprovadoEm` again.
  - `atualizar-kit-video "<folder>" "<projeto>" "<vídeo>"` is her opt-in: it copies the current Kit onto one Vídeo. It refuses a Vídeo that is `Entregue` or `Arquivado`.
- **Kit snapshot**: `projetos/<p>/videos/<v>/kit.json`. A Vídeo reads its own Kit when it has one, and the Projeto's Kit otherwise.
  - `freezeVideoKits` (`lib/projeto.mjs`) runs before an approved Kit changes, through `editar-kit` or a re-run of `aprovar-kit`.
  - `estado` now validates each Vídeo's own Kit against the Kit schema.

## Decisions & deviations
- **The edit arrives as a JSON argument**, not a file or stdin, so the flow stays one Bash call. The skill says to write an apostrophe as `'`. I chose a deep merge over RFC 7396: `null` is a valid Kit value (`aprovadoEm`, `creditos.*`, `cartaoFinal`), so under RFC 7396 it could not mean "delete".
- **Her "aplicar" is the approval of the changed Kit.** `editar-kit` stamps `aprovadoEm` itself, so she does not go through a second Kit Gate. An edit may not set `aprovadoEm` or `schemaVersion`.
- **Only an approved Kit (`kit: ok`) can be edited.** A Projeto that is still in its Grilling is refused with `kit-not-approved`, and the skill routes it to novo-projeto.
- **Vídeos are frozen lazily**, when a Kit changes, not when they are created. This covers existing Vídeos, because #9 does not exist yet. `aprovar-kit` also freezes on a re-approval, which closes that gap.
- **Delivered or archived Vídeos cannot opt in** (`reason: finished`). Their Kit records what they were delivered with (US26: "delivered work does not change").
- **The briefing has no per-Vídeo copy.** It is prose context, and the skill tells her that a Plano she already approved stays as it is.
- **Asset protection for older Kits is a skill rule**, not enforced by the CLI: new assets get new names in `kit/`, and nothing there is overwritten or deleted.
- **I ran `npm ci --ignore-scripts` in the worktree** to make typecheck possible. `node_modules` is gitignored.
