## What was built
- A `SessionStart` hook (`plugin/estudio/hooks/hooks.json`) checks for Node, ffmpeg, ffprobe, Python with faster-whisper and, inside an Estúdio, the Remotion dependencies. It prints one English line for the model only when something is missing, and it never installs.
- A check script, `scripts/verificar.sh` (macOS/Linux) with its twin `verificar.ps1` (Windows). With `--json`/`-Json` it returns `{os, missing[], tools{node,ffmpeg,ffprobe,python}, remotion}`.
- An installer, `scripts/instalar.sh` (macOS/Linux) with its twin `instalar.ps1` (Windows). It runs one step at a time (`node|ffmpeg|python|remotion|tudo`):
  - it puts portable builds in `${CLAUDE_PLUGIN_DATA}/runtime/`: official Node v22.23.3, a static ffmpeg, and uv 0.12.21 → Python 3.12 venv + faster-whisper;
  - it keeps caches in `${CLAUDE_PLUGIN_DATA}/cache/`;
  - it runs `npm install` for Remotion in the Estúdio folder;
  - it narrates in plain pt-BR, skips any step that already works, and leaves nothing half-installed when it fails.
- The `/estudio:estudio` skill runs the check first. When something is missing it asks the one question, "Posso preparar seu computador para editar vídeos? (~10 min, grátis)".
  - "sim" runs the steps and relays the progress lines.
  - "agora não" keeps everything else working.
  - Every program, `estado`/`criar` included, runs by its `tools.*` path.

## Acceptance criteria
- [x] The hook never installs; it reports missing tools. Tests: `the session-start hook reports what is missing…` (bash, asserts that the data and Estúdio folders are untouched), `on Windows without Git Bash the same hook command runs in PowerShell…`, and `on a fresh computer the check reports every missing tool and installs nothing`. A real `claude -p "/estudio:estudio" --plugin-dir …` run showed the hook line in context and the Diretor asking exactly the question.
- [x] The Mac and Windows scripts install without an admin password or OS prompts.
  - Windows: a real `instalar.ps1 tudo` run through WSL interop with a PATH reduced to Windows took 96 s, exit 0, with no admin or UAC. The gated test `on Windows a real install…` passes with ESTUDIO_TESTE_REDE=1.
  - Linux: a real `instalar.sh tudo` run in a sandboxed PATH took 73 s, and nothing was written to `$HOME`. Gated test `a real install puts everything in the plugin data folder…`.
  - macOS: this path has **not been run on a Mac** (the end-to-end run, #19). The mac branch uses the same sh code with the darwin URLs, which were verified to answer HTTP 206.
- [x] No brew/winget/terminal in the Criadora-facing text. The installer output and the hook are asserted against `/\b(brew|homebrew|winget|terminal|sudo|admin)\b/i` in tests. The skill tells the Diretor never to name them. The brew/winget blocks were removed from `references/getting-started.md`.
- [x] A re-run is idempotent, and after install the hook reports nothing missing. Tests:
  - `re-running the installer on a prepared computer downloads nothing…` (no curl on PATH);
  - `the session-start hook stays silent when nothing is missing`;
  - the two real-install tests, where a re-run prints "já estava pronto" ×4 and the check shows `missing: []`.
- [x] Uninstalling the plugin removes the downloaded runtimes. Test: `uninstalling estudio deletes its plugin data folder…` (real `claude plugin uninstall` in an isolated `CLAUDE_CONFIG_DIR`; `plugins/data/estudio-studio` is gone).

## Decisions & deviations
- **The hook command is a bash/PowerShell polyglot:** `` set -- `# <#` ; sh ".../verificar.sh" "${CLAUDE_PLUGIN_DATA}" ; exit 0 ; #> ; powershell … verificar.ps1 -Dados "${CLAUDE_PLUGIN_DATA}" ; exit 0 ``.
  - Claude Code runs hooks with bash, or with PowerShell on Windows without Git Bash. The maintainer's Windows machine has **no Git Bash**, so an sh-only hook would fail there.
  - Both branches were verified: bash/sh/dash in tests, and PowerShell 5.1 via powershell.exe.
- **The plugin data folder is passed inline** (`${CLAUDE_PLUGIN_DATA}` substitution) to the hook and to every skill command, following review finding 2. Substitution inside the skill body was proven by the real `claude -p` run: the path became `~/.claude/plugins/data/estudio-inline`.
- **The per-OS scripts are `.sh` for macOS and Linux (the WSL maintainer path) and `.ps1` for Windows.** `verificar.sh` and `instalar.sh` delegate to the `.ps1` under Git Bash. The `.ps1` files are saved UTF-8 **with BOM**, so PowerShell 5.1 reads the accents correctly.
- **The check never runs OS stubs:** macOS `/usr/bin/python3` (it opens the Command Line Tools window) and the Windows Store `python.exe` (it opens the Store). Either would count as an OS prompt.
- **A tool already on the computer counts as present** (portable is tried first, then PATH), so `tudo` downloads only what is missing.
- **ffmpeg sources:**
  - macOS: martin-riedl "latest release" zips;
  - Linux/Windows: BtbN n9.0 branch builds.
  - Node, uv and Python are pinned; ffmpeg is not pinned per version. The script headers now say so.
- **The skill runs one step per Bash call, with a 10-minute timeout,** so each step stays under the tool limit and the Diretor narrates between steps.
- **Remotion `node_modules/` lives in the Estúdio**, per the spec, and survives uninstall. ADR 0004 was amended to say this and to give the measured size, ~450–650 MB.
- **`.gitattributes` gains `*.sh text eol=lf`.** With `core.autocrlf=true`, a Windows checkout would otherwise break `sh`.
- **`references/getting-started.md`:** §2–3 (upstream brew/winget/clone) were replaced by a description of the installer, and the later sections were renumbered. The anchor in `level-1-remotion.md` was fixed to match.

## Learnings
- A hook command valid in both bash and PowerShell: `` set -- `# <#` ; <bash part> ; exit 0 ; #> ; <PowerShell part> ``.
- PowerShell 5.1 needs `.ps1` files saved as UTF-8 with BOM for accented literals, and `[Console]::OutputEncoding = UTF8` for piped output.
- The maintainer's Windows has no Git Bash, so Claude Code hooks there run in PowerShell.
- The plugin data folder id for `estudio@studio` is `plugins/data/estudio-studio`. With `--plugin-dir` it is `estudio-inline`.
- The worktree has no `node_modules`: run `/usr/bin/npm ci` before `npm run typecheck`.

## Notes for dependent tickets
- Get tool paths with `sh "${CLAUDE_PLUGIN_ROOT}/scripts/verificar.sh" --json "${CLAUDE_PLUGIN_DATA}" "."`, or on Windows `powershell -NoProfile -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}/scripts/verificar.ps1" -Json -Dados "${CLAUDE_PLUGIN_DATA}" -Estudio "."`. Always run `tools.node` / `tools.ffmpeg` / `tools.ffprobe` / `tools.python` by full path, because the portable runtimes are not on PATH.
- `qc`/`precorte` (#… Seam 1) should take the ffmpeg/ffprobe paths as arguments or env from the skill; `estudio.mjs` runs under `tools.node`.
- Transcription (#9/ingest) must run under `tools.python` and **set `HF_HOME` inside `${CLAUDE_PLUGIN_DATA}/cache/`**. faster-whisper otherwise downloads its model weights to `~/.cache/huggingface`, outside the folder that uninstall cleans.
- The layout is documented at the top of `plugin/estudio/scripts/lib/ferramentas.sh` and `ferramentas.ps1`. A new runtime needs an `acha_*`/`Acha*` function, a step in both installers, and an entry in `verificar`.
- Remotion's headless browser (Chrome Headless Shell) is not pre-downloaded. The first render will fetch it into `node_modules`.
