## What was built
- Preparação: new `modelo` step in `plugin/estudio/scripts/instalar.sh` and `instalar.ps1` (also part of `tudo`, between `python` and `remotion`). It reads the `speech-model` files from `plugin/estudio/vendor.json`, downloads each one to a temp folder, moves it into `<plugin data>/modelos/large-v3-turbo/` only after its sha256 matches, deletes and reports (pt-BR) a file that fails, prints `(n de total) baixando <arquivo>…` per file, and skips files already verified (a re-run downloads nothing; a corrupted file already in the folder is replaced).

## Decisions & deviations
- Model folder: `<plugin data>/modelos/large-v3-turbo/` (a subfolder named after the model, as the spec says). The name is a constant in both shared libs and the transcriber default; the manifest has no field for it.
- The check reports missing on presence of the five manifest files (no hashing: model.bin is 1.6 GB and the check runs at every session start). The installer hashes on every run (about 3 s for the full model).
- The transcriber's "prepared" test is lighter than the check's: `model.bin`, `config.json`, `tokenizer.json` and one vocabulary file (`.json` or `.txt`, so other CTranslate2 models such as the opt-in test model still work). The Preparação owns completeness and integrity.
- Manifest parsing in POSIX sh is done with `sed`/`tr` (the sandboxed machine has no Node or jq). It relies on the shape of `vendor.json`: the `speech-model` source is last, and each file lists `name`, `sha256`, `url` in that order with lowercase hex. tests/terceiros.test.mjs now pins that contract. PowerShell uses `ConvertFrom-Json`.
- `ESTUDIO_MODELO_MANIFESTO` is the only override (a manifest with `file://` URLs); no separate base-URL override was needed. PowerShell `Baixa` gained a `file:` branch for it (with `-ErrorAction Stop`; the first version swallowed a missing source, found by the WSL interop test).
- Progress: one `(n de total) baixando <arquivo>…` line per file, no percentage during a single file (curl runs `--silent`). A poller was judged speculative for this ticket.
- The "~15 min" in the preparation question is my estimate (the old text said ~10 min without the model); it is not measured. Change it in SKILL.md, getting-started.md and README.md together if you measure otherwise.
- The transcriber's opt-in test now expects the prepared model in `ESTUDIO_MODELOS/<ESTUDIO_MODELO_TESTE>` (default `large-v3-turbo`, not `tiny`, because nothing downloads any more).
- The Windows twin was exercised here through `powershell.exe` interop (a new test, not network-gated); the real Windows install test stays opt-in.

## Learnings
- A `file://` URL for curl and `[Uri]` must be percent-encoded when the path has spaces or accents (`pathToFileURL`, `encodeURI`), and never encoded twice.
- PowerShell `Copy-Item` without `-ErrorAction Stop` does not throw inside `try`; a wrapper meant to return `$false` on failure returns `$true`.
- `sh` here-documents feeding `while read` end with an empty line; skip empty names.
- The tests sandbox PATH (basic utilities only): a new script dependency such as `sha256sum` must be added to `BASIC_UTILITIES` in tests/preparar.test.mjs.
- `gh issue view` fails on this repo (Projects classic); `gh api repos/rodrigorjsf/studio/issues/N` works. `npm` is broken here; run `node node_modules/typescript/bin/tsc` and `node --test` directly, with a temporary node_modules symlink.
