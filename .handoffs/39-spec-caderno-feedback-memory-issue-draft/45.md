## Decisions & deviations
- Recording: the ticket says "the existing `qc-interno` recording". The `qc-interno` command only accepts a Vídeo being built and moves its Status to QC interno, so it cannot run at Aprovado/Entregue/Arquivado. The loop is recorded with `registrar-video` `somar` counters, the same recording the Quadros' and Entrega QC loops already use (edicao step 5 item 3). Consequence: the per-turn verdicts are not kept on disk and the three-turn cap is held by the Diretor's prompt, not by a CLI counter.
- CLI: no production code changed. `texto-do-post` and `registrar-video` already leave Status and Gate alone; the new CLI tests passed on first run (they pin it, they were not red). The red-first slices were the persona, skill and docs static tests (9 of 12 red before the edits).
- The escalation question at the cap is asked in the closing message, after the delivery, and is not counted in the Vídeo's `perguntas` (step 6 already says questions after the Entrega are not counted). The Revisor-approval rule has one exception: at the cap she may choose to see the text as it is.
- Codes are named in pt-BR kebab style like `area-livre`, `gancho`: `isca-de-engajamento`, `afirmacao-fora-da-transcricao`, `primeira-linha-sem-palavra-chave`, `checagem-mecanica`.
- Engagement bait does not list "follows" (the ticket's list: likes, comments, shares, tags, votes, rewards); the Social media still never asks for follows.
- On request for an older Vídeo whose `texto-do-post.md` already exists, it goes straight to the Revisor and is rewritten only if she asks for a new one.
- #44's "withhold the text and offer a retry when not `pronto`" stays as the fallback; a text failing the mechanical check now also reaches the Revisor as `checagem-mecanica` and loops.
