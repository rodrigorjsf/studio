## Decisions & deviations
- Reference path chosen: `skills/estudio/references/platform-rules.md` (next to the other skill references); constant `PLATFORM_REFERENCE` in `lib/plataforma.mjs`, shared by the check and `estado`.
- Rule format: a rule = any top-level bullet outside a code fence; the label legend is a table, not bullets.
- Clock seam: env var `ESTUDIO_NOW` (ISO date) overrides "now" in `estado` so tests can straddle the 6-month line. Test-only hook shipped in the package; flagged by review, kept (only way to test through the CLI seam).
- `check-plugin` validates the reference only when the file exists (fixtures of other tickets stay valid); the repo's real package is covered by a test that reads the shipped file. A missing reference reports `presente: false, desatualizada: true` in `estado`.
- Provenance weak spots, stated in the rule text: the research gave no URL for the Shorts title limit (100) and hook length, for cutoff lengths, or for the "<=~100 chars" first-line figure. Those rules are `[marketing]`, cite the closest platform page, and say no platform publishes the figure. The maintainer should replace those URLs on the next quarterly refresh if a better source is found.
- Label choices: Shorts description "2 to 3 hashtags" is `[official]` (the research's "official display rule"); the TikTok hashtag count is "3 to 6" as the cited source says (the Social media keeps to 3 to 5). The Instagram filler-tag rule is `[official]` per ADR 0008; the Mosseri hashtag rule is `[official]` via press, as the research labeled it.
